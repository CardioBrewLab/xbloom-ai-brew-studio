# 功能说明

0.2 同时提供浏览器 Hosted 云端版和 Windows 本地工作台。下面的能力矩阵说明当前用户可见的功能边界。

## 能力矩阵

| 功能                  | Hosted 云端版                                                              | Windows 本地版                               |
| --------------------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| 账号和登录            | 多用户注册和登录                                                           | 本地浏览器配置文件                           |
| 用户隔离              | 配方、豆子、历史记录、模型设置和 xBloom 会话按账号隔离                     | 文件和设置按项目/用户保存在本地              |
| BYOK 模型             | OpenAI/GPT、Claude、Kimi、DeepSeek、Qwen、Gemini、自定义 OpenAI-compatible | 通过设置页面或 `.env` 配置本地模型端点和 key |
| 模型发现              | 服务商支持时读取模型列表                                                   | 本地端点支持时读取模型列表                   |
| 模型测试              | 保存个人连接前执行 Test                                                    | 测试本地配置的模型连接                       |
| 冲煮目标              | 支持                                                                       | 支持                                         |
| 调研上下文            | Hosted 内置流程，加上可选的本地助手                                        | 可选本地 SearXNG/Firecrawl/Xiaohongshu 工具  |
| 生成模式              | FAST / PRO / MAX                                                           | FAST / PRO / MAX                             |
| 候选生成              | 由生成路径执行模式策略                                                     | 桌面模式使用本地策略；旧 API 参数可配置      |
| 配方评分和曲线        | 支持                                                                       | 支持                                         |
| 豆子和历史记录        | 按账号保存在 D1                                                            | 保存在本地 data 目录                         |
| xBloom 云端登录和上传 | 每个用户独立登录、列出、更新、删除、上传                                   | Cloud 页面和本地账号流程                     |
| xBloom App 流程       | 使用 Hosted xBloom 云端流程                                                | 使用本地流程，也可以调用 xBloom 云端 API     |

## 冲煮工作流

1. 填写豆子资料、烘焙信息、目标风味、设备和其他约束。
2. 选择 FAST、PRO 或 MAX。
3. 由当前模型按模式策略生成一个或多个候选配方。
4. 查看结构化配方、评分信号和曲线。
5. 将配方保存到当前账号（Hosted）或本地 data 目录（Windows）。
6. 需要时上传到当前用户自己的 xBloom 云端。

模型请求会包含用户在本次流程中选择的冲煮上下文。服务商会按自身条款接收这些请求；凭证仍按配置边界归当前用户或部署运营者所有。

## Hosted 多用户能力

### 账号隔离

每个账号都有自己的配方、豆子、历史记录、模型设置和 xBloom 外部会话。双账号验收需要确认记录、模型配置和 xBloom 状态不会跨账号出现。

### 个人模型设置

用户可以选择服务商，在服务支持时发现模型，执行连接测试，再保存个人设置。Hosted 支持 Anthropic 和 Gemini 原生协议，也支持 OpenAI-compatible 服务。Kimi、DeepSeek 和 Qwen 以各自的服务商预设呈现，并使用兼容协议。

### xBloom 云端同步

Cloud 页面支持每个用户独立登录 xBloom 并执行配方操作。用户可以通过部署提供的云端流程列出、导入/读回、更新、删除和上传配方。Hosted Worker 会把 xBloom 云端会话按用户加密保存。

### 可选本地小红书助手

Hosted 浏览器页面可以配对 `127.0.0.1` 上的本地助手。配对需要用户明确确认，浏览器保存本地配对信息，小红书 Cookie 留在本地助手运行时。调研增强是可选项；没有助手时，生成和 xBloom 操作仍有直接流程。

## Windows 本地能力

- 项目内 Node.js 运行时和锁定的 npm 依赖安装。
- 绑定回环地址的本地 API，以及由 Windows watchdog 启动的浏览器 UI。
- 通过本地 `.env` 或设置页面配置模型。
- 通过本地 data 目录保存配方和豆子。
- 可选 SearXNG、Firecrawl 和 Xiaohongshu MCP 调研渠道。
- 可选 Python BLE 设置，支持兼容的设备流程。
- 本地停止脚本和 watchdog 重启行为。

安装器根据解压后的项目目录计算受管理路径。对于不支持 Windows 工作区链接的文件系统，安装器有物理依赖备用路径；升级时仍建议使用本机可写的 NTFS 目录。

## 运行边界

- Hosted 模型密钥和 xBloom 会话按账号保存；共享模型（guest model）属于部署级备用配置，二者分开。
- 本地 `.env`、`data/`、`.runtime/`、助手状态和 BLE 状态都是用户本地资料，应留在发布压缩包之外。
- Hosted Worker 不提供本地 BLE 设备实验室。
- 本地助手不会把 Hosted 浏览器会话变成共享的小红书登录；每台电脑维护自己的助手状态。
- 模型服务商可能收到请求中的冲煮笔记、豆子资料、调研上下文和配方指令。生成前请移除无关个人信息。

## 验证说明

仓库的验证命令是：

```powershell
npm run verify
```

测试和检查数量会随当前检出版本变化。请以当前 `npm run verify` 的实际输出为准，不在文档中固定数量。
